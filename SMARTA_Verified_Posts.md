## Verification methodology note (read first)

In this research environment, direct `WebFetch` requests to `instagram.com` are blocked by Instagram's bot-protection layer and return **HTTP 403 Forbidden** for every URL tested (confirmed on multiple candidate posts across account types, including large global brands). This is an Instagram-side block on automated/datacenter fetches, not a proxy or tooling failure.

Because of this, every URL below was verified using the fallback method explicitly allowed by the brief: **`WebSearch` cross-check**. Concretely, each URL was surfaced by a keyword search (not guessed or pattern-generated), and the search engine returned that exact `instagram.com/p/…` or `instagram.com/{account}/p/…` URL together with a **title/snippet independently scraped by the search engine's own crawler** — i.e., third-party confirmation that (a) the post exists/is publicly indexed, (b) it belongs to the stated account (the handle appears in the URL path and/or title), and (c) the caption content matches the stated theme keywords. This is recorded per post as "Verification: WebSearch — indexed title/snippet match."

Where a candidate URL could **not** be re-confirmed by a second, independent search pass, it was **discarded** and replaced — per the hard "no fabrication" rule, nothing below was written from memory or pattern-guessed from an account's URL scheme. Engagement metrics (likes/comments) are not available via this method — see Transparency Report.
